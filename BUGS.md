# Отчёт о найденных багах (Lab2, консольный поиск по Википедии)

Дата тестирования: 2026-11-09
Окружение: Linux, OpenJDK 21.0.12, Gson 2.13.1. Запуск: `./build.sh run` (classpath с Gson).

.

## Приоритет 1 — падения / потеря управления

### 1. EOF (Ctrl+D) на приглашении запроса = падение

Файл: `src/Main.java:15`

`scan.nextLine()` при закрытом stdin бросает необработанный `NoSuchElementException`.

Воспроизведение:

```bash
printf '' | ./build.sh run
```

Фактически:

```
Exception in thread "main" java.util.NoSuchElementException: No line found
    at java.base/java.util.Scanner.nextLine(Scanner.java:1660)
    at Main.main(Main.java:15)
```

Ожидаемо: корректный выход из цикла.

### 2. Из режима выбора нельзя выйти; `exit` там приводит к исключению и последующему падению

Файл: `src/Main.java:32`

На приглашении «Выберите нужный вам вариант» ввод `exit` попадает в `Integer.parseInt` и бросает `NumberFormatException` (ловится общим `catch`, печатается стектрейс). После этого программа снова просит запрос; если stdin закончился — падение из п.1.

Воспроизведение:

```bash
printf 'test\nexit\n' | ./build.sh run
```

Ожидаемо: `exit` завершает программу из любого приглашения.

## Приоритет 2 — некорректные ответы API и сеть

### 3. Пустой запрос = NPE в Parser

Файлы: `src/Main.java:18`, `src/Parser.java:36`

Запрос пустой строки отправляется как `srsearch=`; API отвечает HTTP 200 с телом:

```json
{"error":{"code":"missingparam","info":"The \"srsearch\" parameter must be set."}}
```

Parser ожидает `query.search`, получает `null` и падает с `NullPointerException` (печатается стектрейс).

Воспроизведение:

```bash
printf '\n0\nexit\n' | ./build.sh run
```

Ожидаемо: не отправлять пустой запрос (или обрабатывать поле `error` и сообщать пользователю).

### 4. Слишком длинный запрос = NPE или 414 без пояснения

Файлы: `src/Requester.java:16-17`, `src/Parser.java:36`

- ~2000 символов: API отвечает 200 с объектом `error`, Parser падает с NPE (как в п.3).
- ~9000 символов: HTTP 414, выводится «Cry baby. Код ответа сервера: 414».

Воспроизведение:

```bash
python3 -c "print('a'*2000)" | { read q; printf '%s\n0\nexit\n' "$q"; } | ./build.sh run
```

Ожидаемо: ограничение длины запроса и понятное сообщение.

### 5. Нет таймаутов HTTP — программа может зависнуть навсегда

Файл: `src/Requester.java:14-21`

Не заданы `setConnectTimeout()` / `setReadTimeout()`. При «зависшем» соединении приложение не вернёт управление.

### 6. HTTP 429 (rate limit) не обрабатывается

Файл: `src/Main.java:43-45`, `src/Requester.java:21`

При частых запросах Википедия отдаёт 429, пользователь видит только:

```
Cry baby. Код ответа сервера: 429
```

Нет retry/backoff, задержки, понятного текста. Воспроизводится серией быстрых запросов подряд.

### 7. Утечка соединений

Файл: `src/Requester.java:18`

Перед созданием нового `HttpURLConnection` старый не закрывается; `disconnect()` вызывается только при выходе из программы. При долгой сессии соединения накапливаются.

### 8. Parser не устойчив к неожиданному JSON

Файл: `src/Parser.java:32-52`

Проверенные кейсы (вход подсовывался напрямую в `Parser`):

| Вход | Результат |
|---|---|
| нет `query` | `NullPointerException` |
| нет `search` | `NullPointerException` |
| `search: null` | `ClassCastException` |
| элемент `search` не объект | `IllegalStateException` |
| нет `title` | `NullPointerException` |
| нет `pageid` | `NullPointerException` при `getPageId` |
| битый JSON | `JsonSyntaxException` |
| пустой поток | `IllegalStateException` |

`Main` ловит всё общим `catch (Exception)` и печатает стектрейс вместо понятного сообщения.

### 9. `getPageId` без проверки границ

Файл: `src/Parser.java:50-52`

`getPageId(0)`, `getPageId(-1)`, `getPageId(size+1)` → `IndexOutOfBoundsException`. Сейчас защищено только валидацией в `Main.java:34`; метод лучше сделать безопасным самостоятельно.

## Приоритет 3 — косметика и UX

### 10. Заголовки выводятся в кавычках

Файл: `src/Parser.java:44`

Используется `el.get("title").toString()`, поэтому в консоли `1) "Test"` вместо `1) Test`. Нужен `getAsString()`.

### 11. Неверный текст о количестве результатов

Файл: `src/Main.java:26`

«Было найдено N совпадений» показывает размер страницы (по умолчанию максимум 10), а не общее число найденных статей (`totalhits`). Пользователь не видит и не может выбрать результаты после 10-го.

### 12. Команда выхода неудобна и неочевидна

Файл: `src/Main.java:16`

- Чувствительна к регистру: `Exit`, `EXIT` — это поисковые запросы.
- Пробелы не обрезаются: ` exit`, `exit ` — тоже поиск.
- Слово `exit` нельзя использовать как поисковый запрос.
- Из режима выбора выйти нельзя (см. п.2).

### 13. Опечатки в сообщениях

Файл: `src/Main.java:35`

«Введеного вами числа нет в допустимом диапозоне» → «Введённого вами числа нет в допустимом диапазоне».

### 14. Зависимость от кодировки платформы

Файлы: `src/Main.java:11`, `src/Main.java:14`

`Scanner(System.in)` и `System.out` используют кодировку по умолчанию. На не-UTF-8 локали кириллический ввод/вывод может ломаться. Явно задать `InputStreamReader(System.in, StandardCharsets.UTF_8)` и `PrintStream(..., UTF_8)`.

### 15. Проблемы сборки/окружения

- `build.sh` работает только из корня проекта (относительные `src`/`out`) и содержит жёсткий путь к Gson в `~/.m2`.
- `pom.xml` требует `maven.compiler.release=24`, а установлен JDK 21; `mvn` в системе отсутствует.

### 16. Прочее

- `new URL(...)` в `Requester.java:17` — deprecated (предупреждение компилятора).
- `Scanner` не закрывается.
- Общий `catch (Exception)` в `Main.java:40` скрывает реальные причины за стектрейсами.
- В headless-режиме выбор статьи даёт `HeadlessException` со стектрейсом (`Main.java:53`); для GUI-окружения не критично.

## Что работает корректно (проверено)

- Сборка через `./build.sh`.
- Обычные запросы (`test`, `QF-Test`, кириллица, `C++`, символы `a&b=c?d#e`, эмодзи).
- Ноль результатов: сообщение и возврат к приглашению без падения.
- Валидация выбора `0`, `-5`, `999` после исправления границ.
- Выход `exit` из главного приглашения.
- Сетевой отказ (мёртвый прокси) → код `-1` и сообщение, без падения.
- `disconnect()` при `connection == null`.
